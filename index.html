04 — SETUP

Connect a wallet. Create an API wallet.

Hyperliquid does not issue a classic exchange API key. You must first connect your master wallet, deposit USDC from your wallet into the exchange, and then authorize an API wallet. The API wallet can sign trades. It cannot withdraw.

01

Connect the master wallet

Open app.hyperliquid.xyz and connect MetaMask, Rabby, or WalletConnect. Sign the connection request. That signature identifies the account. It does not grant TrustAlgo, or the API wallet, withdrawal rights.

02

Deposit USDC to the exchange

Connecting your wallet is not enough. You must actively transfer USDC from your personal wallet into your Hyperliquid account. Click "Deposit" in the app to bridge your funds (minimum 5 USDC). Wait until the balance shows on Hyperliquid before creating the API wallet. The algorithm can only trade with the balance actually deposited on the exchange.

03

Open the API page

Go to More, then API, or open app.hyperliquid.xyz/API. An API wallet is an agent wallet: it signs for the master account. Info requests still use the master address, not the agent address.

04

Name it, then generate

Enter a name, for example trustalgo. Click Generate. A named wallet is easier to track. An account can keep one unnamed API wallet and up to three named ones. Approving a new wallet with the same name replaces the previous one.

05

Copy the private key, then authorize

The dialog shows the private key once. Copy it into a password manager before you authorize. Then click Authorize API Wallet and sign with the master wallet. Default validity is 90 days. The maximum is 180 days. Hyperliquid will not show the key again.

06

Provision your node

Keep the master address and the API wallet private key separate. The master address is the account. The private key is the signer. Proceed to the secure Onboarding section below to provision your node. You can revoke the API wallet on the Hyperliquid API page at any time.

Scope. The API wallet can place and manage orders. It cannot withdraw. Withdrawals stay on the master wallet. If the key is lost, generate a new API wallet. Do not reuse a deregistered agent address.

05 — SECURITY ARCHITECTURE

The API key lifecycle.

No private key is ever written in plaintext to disk or database. TrustAlgo's infrastructure uses a four-phase data isolation protocol to ensure the Agent Wallet remains protected.

1. TRANSMISSION

Encrypted tunnel. When you enter the private key on the site, the data does not travel over the public internet. The connection uses an encrypted TLS tunnel (Cloudflare Tunnel) that routes the payload directly to the isolated backend.

2. CRYPTOGRAPHY

Immediate AES-256-GCM. As soon as the server receives the payload, the API key is instantly encrypted in memory using the AES-256-GCM (Authenticated Encryption with Associated Data) standard. The system does not execute any plaintext logging of the key.

3. STORAGE

Zero-knowledge database. The TrustAlgo PostgreSQL database strictly stores three encrypted strings: the ciphertext, the initialization vector (IV), and an authentication tag. The Master Key required to decode this data is physically isolated and does not reside in the database.

4. EXECUTION

In-memory decryption. The key is decrypted exclusively by the worker process tasked with dispatching orders to Hyperliquid. Decryption occurs in memory (RAM) a fraction of a second before signing the order. Once dispatched, the plaintext string is immediately destroyed.
